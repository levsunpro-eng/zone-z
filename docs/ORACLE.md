# Бесплатный сервер ZoneZ на Oracle Cloud

Выбран Oracle Always Free. Публичный сервер ещё не создан: сначала нужно завершить регистрацию аккаунта. Игровая сборка находится в `Builds/Online`, готовый архив для друзей — `Builds/ZoneZ-0.2.0-online.zip`. Боты работают без облака.

## Сначала — регистрация

Откройте [официальную регистрацию Oracle Cloud](https://signup.cloud.oracle.com/), подтвердите почту, телефон и карту на сайте Oracle. В домашнем регионе создаются бесплатные Compute-ресурсы; если доступен Frankfurt, он подходит как исходный выбор для друзей в Европе. Карта может получить временную блокировку суммы для проверки. [Условия регистрации](https://www.oracle.com/cloud/free/).

После регистрации войдите в Cloud Console. Для следующего шага достаточно сообщить, что вход выполнен. Пароль, код подтверждения, данные карты и приватный SSH-ключ в чат не нужны.

## Ресурсы для одного сервера

Используйте Ubuntu 24.04 и **одну** машину с пометкой **Always Free eligible**:

| Параметр | Выбор |
|---|---|
| Имя | `zonez-lobby` |
| Shape | `VM.Standard.A1.Flex`, 1 OCPU и 1 GB RAM; либо `VM.Standard.E2.1.Micro` |
| Boot volume | 50 GB, без дополнительных томов |
| Сеть | Public subnet с Internet Gateway и публичным IPv4 |
| Авторизация SSH | Свой публичный ключ или сохранённая локально пара ключей Oracle |
| Приложение | Python, служба systemd, до 64 соединений |

Это конфигурация допуска, её нагрузочная ёмкость пока не измерена. Всего Always Free для A1 сейчас даёт 2 OCPU и 12 GB RAM, для дисков — 200 GB. Сверьте остатки квот и бесплатную пометку перед созданием; обычная trial-машина за кредиты не равна Always Free. Если нет свободной мощности, попробуйте другой Availability Domain в домашнем регионе или позднее. Oracle может изъять малоиспользуемый бесплатный Compute. [Актуальные бесплатные ресурсы](https://docs.oracle.com/en-us/iaas/Content/FreeTier/freetier_topic-Always_Free_Resources.htm).

Порядок создания VM и сети описан в [официальной инструкции Oracle](https://docs.oracle.com/en-us/iaas/Content/Compute/tutorials/first-linux-instance/overview.htm). Для нашего установщика выбирайте именно Ubuntu, хотя пример Oracle использует Oracle Linux. Учётная запись Ubuntu для SSH — `ubuntu`.

## Порты

В Security List или NSG публичной подсети добавьте stateful ingress TCP с исходными портами All:

| Назначение | Destination port | Source CIDR |
|---|---|---|
| Проверка и обновление сертификата | 80 | `0.0.0.0/0` |
| Лобби, поиск, игровые сообщения по TLS | 7780 | `0.0.0.0/0` |
| Управление SSH | 22 | Публичный IP администратора с `/32` |

Сохраните SSH-доступ перед изменениями. Для пакетов ОС и сертификата нужен исходящий доступ в интернет. Аналогичные разрешения нужны в firewall самой VM. Установщик умеет добавить правила для 80/7780 без очистки существующих правил; он не изменяет Security List Oracle. Внешний порт 80 обслуживается Certbot только во время проверки сертификата. По 7780 работает игровой протокол, браузер его не откроет.

## Пакет и установка

Из корня проекта на Windows:

```powershell
.\tools\package-oracle.ps1
```

Получится `Builds/ZoneZ-Oracle-server.zip`. Пакет содержит сервер, установщик и инструкции; игровые ассеты и личные сохранения туда не входят. Замените `PUBLIC_IP` и путь ключа реальными значениями:

```powershell
scp -i 'ПУТЬ_К_КЛЮЧУ' .\Builds\ZoneZ-Oracle-server.zip ubuntu@PUBLIC_IP:zonez-server.zip
ssh -i 'ПУТЬ_К_КЛЮЧУ' ubuntu@PUBLIC_IP
```

В SSH-сеансе Ubuntu:

```sh
sudo apt-get update
sudo apt-get install -y unzip
mkdir -p "$HOME/zonez-server"
unzip -o "$HOME/zonez-server.zip" -d "$HOME/zonez-server"
cd "$HOME/zonez-server"
bash server/oracle/install.sh --plan --public-ip PUBLIC_IP --email YOUR_EMAIL
sudo bash server/oracle/install.sh --public-ip PUBLIC_IP --email YOUR_EMAIL --agree-tos --configure-firewall
```

`--plan` показывает действия без изменения системы. `--agree-tos` принимает условия Let's Encrypt для бесплатного сертификата. `--configure-firewall` нужен, если эти порты ещё не разрешены в firewall ОС. Скрипт предназначен для отдельной Ubuntu 24.04 VM; запускать его на компьютере с другими сервисами без проверки плана не следует.

Сертификат выпускается на реальный публичный IPv4. Домен покупать не нужно. Короткие IP-сертификаты Let's Encrypt автоматически обновляются, а служба перечитывает новую пару через SIGHUP. Уже установленные игровые соединения продолжают работать. [Поддержка IP-сертификатов](https://letsencrypt.org/2026/01/15/6day-and-ip-general-availability/), [поддержка Certbot](https://letsencrypt.org/2026/03/11/shorter-certs-certbot/).

## Проверка из игры

В игре у всех друзей используйте `tls://PUBLIC_IP:7780`, подставив IP своей VM. После действительного размещения и проверки запишите этот адрес одной строкой в `Builds/Online/online-server.txt` и заново упакуйте сборку командой `tools/package-online.ps1` — адрес заполнится автоматически при запуске.

Проверка настоящего сервера тремя копиями Windows-игры в двух режимах:

```powershell
.\tools\test-lobby-game.ps1 -Executable .\Builds\Online\ZoneZ.exe -ServerEndpoint 'tls://PUBLIC_IP:7780'
```

Она использует отдельные временные профили, создаёт тестовые лобби, проверяет приглашение, поиск людей, передачу управления и отдельный запуск с ботами. Внешний режим не запускает и не останавливает облачный сервер. Он подтверждает путь компьютер → Oracle → компьютер; дополнительно нужен вход друга из другой домашней сети.

После проверки лидер создаёт лобби и передаёт друзьям код. Для автоматического поиска нужна вторая независимая группа на этом же сервере. Боты доступны отдельной кнопкой и локально без интернета. Если игровой хост выйдет, матч закончится.

## Текущий статус

Локально прошли девять серверных интеграционных сценариев, включая смену сертификата без потери лобби; одиннадцать unit-тестов установщика сертификата с подменёнными системными вызовами; проверка Bash-синтаксиса четырёх скриптов. Инструкция и файлы упакованы в `Builds/ZoneZ-Oracle-server.zip` без приватных ключей и тестовых сертификатов. Ubuntu, systemd и выпуск настоящего сертификата этим не проверены.

Подготовка установки и локальные тесты не подтверждают, что публичный сервер уже работает. Успешная регистрация, создание VM, выпуск доверенного сертификата и внешний прогон остаются отдельными фактическими шагами. Адрес и результаты записываются после их выполнения.
